# 01. Resumen Ejecutivo

## 1. Introducción

Este documento presenta la visión general del frontend de TechSupply SCM, definiendo su propósito, alcance, principios arquitectónicos y objetivos de diseño.

Su finalidad es servir como punto de partida para el desarrollo de la interfaz de usuario y establecer las bases que guiarán las decisiones técnicas durante toda la implementación del proyecto.

---

### 1.1 Propósito del Frontend

El frontend tiene como propósito transformar procesos logísticos complejos en flujos de trabajo claros, intuitivos y eficientes para el operador, permitiéndole ejecutar sus tareas con el menor número de pasos posible y con una visualización precisa del estado de cada proceso.

---

### 1.2 Objetivo General

Diseñar una aplicación web moderna, intuitiva y escalable que permita interactuar con los servicios del backend de TechSupply SCM, facilitando la gestión de los procesos de logística de salida (Outbound) mediante una interfaz orientada al operador del sistema.

El frontend será responsable exclusivamente de la presentación de la información, la interacción con el usuario y el consumo de la API REST desarrollada en Node.js.

Toda la lógica de negocio permanecerá centralizada en el backend.

---

### 1.3 Objetivos de Diseño

La interfaz priorizará la claridad operativa sobre la complejidad visual. Cada pantalla estará diseñada para facilitar la ejecución de procesos de negocio mediante una navegación consistente, componentes reutilizables y una distribución de información orientada a la productividad del operador.

---

## 2. Alcance

### 2.1 Alcance del MVP

El frontend implementará únicamente los módulos correspondientes al Grupo 2 (Outbound), de acuerdo con el alcance definido para el proyecto académico.

Los módulos incluidos serán:

- Dashboard
- Gestión de Clientes
- Gestión de Ubicaciones
- Gestión de Pedidos
- Gestión de Detalles de Pedido
- Gestión de Rutas
- Gestión de Despachos

Si el tiempo del proyecto lo permite, se incorporará adicionalmente:

- Inicio de sesión (Login)

---

### 2.2 Alcance Futuro

Aunque el MVP se centra únicamente en Outbound, la arquitectura del frontend será diseñada desde el inicio para permitir la futura incorporación del módulo Inbound sin necesidad de reorganizar la estructura del proyecto.

Esto permitirá integrar posteriormente funcionalidades como:

- Gestión de Proveedores
- Órdenes de Compra
- Recepción de Mercadería
- Gestión de Inventario
- Predicción de Demanda mediante IA

manteniendo una única aplicación React.

---

## 3. Principios del Proyecto

### 3.1 Principios Arquitectónicos

El frontend seguirá los siguientes principios durante todo su desarrollo:

- Separación de responsabilidades.
- Componentes reutilizables.
- Consumo desacoplado de la API.
- Navegación clara y consistente.
- Escalabilidad modular.
- Mantenibilidad del código.
- Experiencia de usuario orientada a procesos de negocio.

La aplicación evitará concentrar lógica de negocio en la interfaz, delegando todas las reglas de negocio al backend.

---

### 3.2 Usuario Objetivo

Durante el MVP, la aplicación estará orientada principalmente a un operador del sistema encargado de ejecutar procesos relacionados con la logística de salida.

El usuario interactuará con módulos de gestión, consultas y operaciones logísticas mediante una interfaz diseñada para facilitar la ejecución de tareas administrativas de forma rápida y consistente.

En futuras versiones podrán incorporarse nuevos perfiles de usuario, manteniendo la misma arquitectura de la aplicación.

## 4. Arquitectura General

### 4.1 Visión General

```text
                    Usuario
                        │
                        ▼
                Aplicación React
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
     Layouts         Pages        Components
        │               │               │
        └───────────────┼───────────────┘
                        ▼
                   Services
                        ▼
                   Axios Client
                        ▼
               API REST (Node.js)
                        ▼
                     MySQL
```

El frontend nunca accederá directamente a la base de datos ni a los servicios externos.

Toda comunicación se realizará exclusivamente mediante la API REST.

---

### 4.2 Relación con el Backend

El frontend constituye la capa de presentación del sistema.

Su responsabilidad consiste en:

- Mostrar la información proveniente del backend.
- Capturar las acciones realizadas por el operador.
- Consumir los endpoints de la API REST.
- Presentar mensajes de éxito o error.
- Guiar al usuario durante los procesos de negocio.

No será responsable de:

- Validaciones de negocio.
- Persistencia.
- Acceso a base de datos.
- Ejecución del algoritmo A*.
- Automatizaciones mediante n8n.

Estas responsabilidades permanecerán completamente desacopladas dentro del backend.

---

## 5. Filosofía de Desarrollo

El desarrollo del frontend seguirá exactamente la misma metodología utilizada durante la construcción del backend.

Cada funcionalidad recorrerá las siguientes etapas:

```text
Análisis
    ↓
Diseño
    ↓
Documentación
    ↓
Validación
    ↓
Implementación
    ↓
Refactorización
```

Esto permitirá construir una aplicación consistente, mantenible y preparada para evolucionar hacia un sistema de gestión de suministros completo.

---

## 6. Visión del Proyecto

El proyecto académico implementará únicamente los módulos correspondientes a Outbound.

Sin embargo, toda la arquitectura del frontend será diseñada pensando en la evolución futura hacia un único sistema TechSupply SCM que integre los procesos de logística de entrada (Inbound) y logística de salida (Outbound) dentro de una misma aplicación.

La estructura propuesta permitirá incorporar nuevos módulos sin modificar la arquitectura existente, favoreciendo la escalabilidad y el mantenimiento a largo plazo.

## 8. Decisiones Arquitectónicas

Durante el diseño del frontend se adoptaron las siguientes decisiones:

- React será el framework principal de la aplicación.
- Se utilizará JavaScript (ES6+) en lugar de TypeScript para mantener la simplicidad del MVP.
- Axios centralizará toda la comunicación con la API REST.
- Bootstrap será el sistema base de estilos.
- React Router gestionará toda la navegación.
- Redux no será incorporado en esta primera versión.
- Toda la lógica de negocio permanecerá exclusivamente en el backend.
