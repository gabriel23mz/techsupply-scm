# 03. Tecnologías

## 1. Introducción

Este documento describe el conjunto de tecnologías seleccionadas para el desarrollo del frontend de TechSupply SCM.

La selección de cada herramienta responde a criterios de simplicidad, mantenibilidad, productividad y compatibilidad con el alcance del proyecto.

El objetivo no consiste únicamente en listar las tecnologías utilizadas, sino justificar las decisiones adoptadas durante el diseño de la aplicación.

---

## 2. Criterios de Selección

Las tecnologías utilizadas en el frontend fueron seleccionadas considerando los siguientes criterios:

- Facilidad de aprendizaje.
- Amplia adopción por la comunidad.
- Compatibilidad con el ecosistema JavaScript.
- Bajo nivel de complejidad para un MVP.
- Escalabilidad para futuras ampliaciones.
- Integración sencilla con el backend desarrollado en Node.js.

---

## 3. Stack Tecnológico

| Categoría | Tecnología |
|-----------|------------|
| Framework | React |
| Bundler | Vite |
| Lenguaje | JavaScript (ES6+) |
| Enrutamiento | React Router |
| Comunicación HTTP | Axios |
| Estilos | Bootstrap |
| Iconografía | Bootstrap Icons |
| Notificaciones | React Toastify |
| Control de Versiones | Git |
| Repositorio | GitHub |

---

## 4. Tecnologías Principales

### 4.1 React

React será utilizado como framework para la construcción de toda la interfaz de usuario.

Su modelo basado en componentes permitirá desarrollar interfaces reutilizables, mantenibles y fácilmente escalables.

**Razones de la elección**

- Arquitectura basada en componentes.
- Gran comunidad.
- Amplio ecosistema.
- Excelente integración con Vite.
- Compatible con proyectos pequeños y grandes.

---

### 4.2 Vite

Vite será utilizado como entorno de desarrollo y construcción del proyecto.

**Razones de la elección**

- Inicio extremadamente rápido.
- Recarga instantánea (Hot Module Replacement).
- Configuración sencilla.
- Excelente integración con React.

---

### 4.3 JavaScript

El desarrollo del frontend utilizará JavaScript moderno (ES6+) aprovechando características como:

- Módulos.
- Funciones flecha.
- Desestructuración.
- Promesas.
- Async/Await.

Esta elección mantiene coherencia con el backend desarrollado en Node.js.

---

### 4.4 React Router

React Router será el encargado de gestionar la navegación dentro de la aplicación.

Permitirá construir una Single Page Application (SPA), donde el cambio entre pantallas se realiza sin recargar completamente el navegador.

**Beneficios**

- Navegación rápida.
- Mejor experiencia de usuario.
- Organización clara de rutas.
- Escalabilidad.

---

### 4.5 Axios

Toda la comunicación entre el frontend y el backend se realizará mediante Axios.

Se utilizará una única instancia configurada para centralizar:

- URL base de la API.
- Configuración común.
- Manejo uniforme de errores.
- Futuros interceptores para autenticación.

**Razones de la elección**

- API sencilla.
- Amplia adopción.
- Mejor organización respecto a `fetch` para proyectos medianos.

---

### 4.6 Bootstrap

Bootstrap será utilizado como sistema base de estilos.

Su utilización permitirá construir interfaces consistentes, responsivas y rápidas de desarrollar.

No se modificará el núcleo del framework.

Las personalizaciones se realizarán mediante estilos propios cuando sea necesario.

**Beneficios**

- Sistema Grid.
- Componentes listos para usar.
- Diseño responsive.
- Consistencia visual.

---

### 4.7 Bootstrap Icons

Bootstrap Icons proporcionará un conjunto consistente de iconos utilizados en toda la aplicación.

Su integración con Bootstrap permite mantener uniformidad visual.

---

### 4.8 React Toastify

React Toastify será utilizado para mostrar notificaciones no intrusivas relacionadas con:

- Operaciones exitosas.
- Errores.
- Advertencias.
- Información.

Las notificaciones seguirán un formato uniforme en toda la aplicación.

---

### 4.9 Git

Todo el desarrollo será gestionado mediante Git.

Permitirá mantener un historial completo del proyecto y facilitar futuras colaboraciones.

---

### 4.10 GitHub

El código fuente del proyecto será almacenado en GitHub.

Esto permitirá:

- Control de versiones.
- Respaldo del proyecto.
- Gestión del desarrollo.
- Evolución futura del sistema.

---

## 5. Tecnologías Evaluadas

### 5.1 Redux

No será utilizado durante el MVP.

La complejidad del sistema no justifica incorporar un gestor de estado global de gran escala.

La combinación de Context API y hooks de React resulta suficiente para los requerimientos actuales.

---

### 5.2 TypeScript

Aunque TypeScript aporta mayor robustez en proyectos grandes, para el alcance del MVP se decidió utilizar JavaScript con el objetivo de mantener coherencia con el nivel académico del proyecto y reducir la complejidad inicial.

La arquitectura propuesta permitirá incorporar TypeScript en futuras versiones si fuese necesario.

---

### 5.3 Tailwind CSS

Se evaluó el uso de Tailwind CSS como framework de estilos.

Sin embargo, Bootstrap fue seleccionado por ofrecer un conjunto amplio de componentes prediseñados que aceleran el desarrollo del MVP.

---

## 6. Compatibilidad con el Backend

El frontend ha sido diseñado para integrarse completamente con el backend desarrollado en Node.js mediante una API REST.

La comunicación entre ambas aplicaciones utilizará exclusivamente el formato JSON.

Toda la lógica de negocio permanecerá centralizada en el backend.

---

## 7. Preparación para el Futuro

La selección tecnológica realizada permitirá incorporar posteriormente funcionalidades como:

- Autenticación mediante JWT.
- Protección de rutas.
- Gestión de roles.
- Módulo Inbound.
- Panel administrativo completo.
- Dashboard con indicadores.

Sin modificar la arquitectura base de la aplicación.

---

## 8. Conclusión

El stack tecnológico seleccionado ofrece un equilibrio entre simplicidad, productividad y escalabilidad.

Las herramientas elegidas permiten desarrollar una aplicación moderna, mantenible y preparada para evolucionar hacia una solución integral de gestión de suministros, manteniendo coherencia con la arquitectura definida para TechSupply SCM.

---

## 9. Decisiones Arquitectónicas

Durante el diseño del frontend se adoptaron las siguientes decisiones:

- React será el framework principal de la aplicación.
- Se utilizará JavaScript (ES6+) en lugar de TypeScript para mantener la simplicidad del MVP.
- Axios centralizará toda la comunicación con la API REST.
- Bootstrap será el sistema base de estilos.
- React Router gestionará toda la navegación.
- Redux no será incorporado en esta primera versión.
- Toda la lógica de negocio permanecerá exclusivamente en el backend.
